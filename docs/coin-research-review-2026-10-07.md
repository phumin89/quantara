# Coin Scout and source Researcher — 2026-10-07

The isolated Live company can now feed meetings with public market discovery and document-backed findings. This release changes advisory evidence and saved reports, not the owner's capital limits, broker permissions or deterministic RiskEngine.

## Implemented behavior

- Scout reads Bitkub public symbols and tickers for THB exchange Spot markets. It retains up to three execution/held markets and ranks up to five other active, unfrozen markets by quote volume, absolute daily change and symbol. New candidates need volume of at least max(100,000 THB, 100 times the permitted order notional), spread at most 0.5%, and sufficient bid/ask depth within the existing slippage limit. Rejected depth candidates are not backfilled in this bounded scan. Thin monitored markets remain visible with a gap; discovery never expands execution authority.
- Public scans are cached for 15 minutes in the company process. Research starts only with a valid, activated, reconciled account packet; it can run before the first daily meeting or while an hourly meeting slot is already used. Portfolio meetings and orders retain their existing schedule and pending-order guards.
- Researcher reads six fixed public sources for BTC, ETH and SOL. Documents cannot choose another URL. The source HTTP client uses HTTPS, no cookies and no redirects, with bounded responses and timeouts. PDFs use Poppler `pdftotext` in the company image; HTML extraction uses the main article. Extracted text is capped at 60,000 characters, with explicit partial-reading disclosure.
- Each source ID is `doc-` plus SHA-256 of its URL and normalized extracted text. Original bytes have a separate SHA-256 checksum. Immutable per-version JSON retains extracted text and the raw-byte mapping; the URL cache may refresh after 24 hours without deleting the cited version.
- AI receives only the public document dossier. It has no broker credentials or financial capability. A finding must identify the matching coin/source and copy a 20–400-character contiguous quotation. Publisher claims, contradictions and uncertainty remain distinct; official documentation is not an independent audit or investment-quality certification.
- Source findings reuse immutable artifacts keyed by document IDs, truncation, prompt and model, across polling, date changes and restarts. Invalid output is cached as rejected evidence; malformed JSON gets an invalid-output marker. Transport failures remain explicit gaps. New document content or a changed prompt/model requires a fresh analysis.
- The full daily meeting remains eight roles. Price/portfolio reviews remain three roles; a changed shortlist or document conclusion adds Scout and asset analysis for a five-role review. Meetings stay at most once per Bangkok hour. Public-read latency refreshes the financial packet and review hour before a claim; day changes stop the attempt.
- A saved meeting includes the bounded shortlist, document identities, findings, exact quotations, observation/retrieval times and gaps. Reports are persisted through the existing owner database path and replayed idempotently. Historic reports validate evidence age at their original observation, so they remain readable weeks later. Old journal summaries without research retain their original envelope hashes.

## Interface review

The existing team room still opens with the final conclusion. One closed native disclosure, “เหรียญและหลักฐานที่ทีมตรวจ”, contains the shortlist and research. Citations open the verified public source; quotations have their own disclosure. Research-only markets and missing evidence are explicit. Raw model/provider field names stay out of the reading flow.

An isolated preview rendered the actual components with synthetic content at 1440, 768 and 390 pixels. No account or financial controls were connected. All three layouts had no horizontal page overflow; source text wrapped, disclosures had 44-pixel targets and keyboard focus styling, and the inherited monochrome typography remained intact. Review found undersized disclosure targets and fixed them before the confirmation pass. The colored Office remains present; the preview does not prove production agent activity.

## Sources and remaining limits

The curated catalog is [Bitcoin paper](https://bitcoin.org/bitcoin.pdf), [Bitcoin Core security policy](https://raw.githubusercontent.com/bitcoin/bitcoin/master/SECURITY.md), [Ethereum original paper](https://ethereum.org/whitepaper/), [Ethereum current PoS](https://ethereum.org/developers/docs/consensus-mechanisms/pos/), [Solana original paper](https://solana.com/solana-whitepaper.pdf) and [Solana core concepts](https://solana.com/docs/core). Public market parsing follows [Bitkub REST v3](https://github.com/bitkub/bitkub-official-api-docs/blob/master/rest-v3.md).

The ETH original paper is historic and exceeds the extraction limit. Current docs supplement it but do not make this complete due diligence. Other Scout coins have no curated document assessment yet; independent audits, current unlocks, ownership concentration and incident records are unknown unless supplied. Selection is a liquidity screen, not a prediction of profit.

This turn built and verified release images; it did not replace production containers, activate financial authority, submit/cancel a broker order, or prove a profitable Live trade. Docker restart invokes the existing executor recovery suspension. To install the checked build and intentionally activate within the existing owner policy, the owner uses `Enable Auto Trading.cmd`; no new manual buy/sell receipt requirement was introduced. Real app execution and durable recovery against the broker remain separate from these synthetic test results.
