# Auto trade path review — 2026-10-06

The current path no longer asks the owner to sell existing BTC or complete a manual canary round trip. This round implements authenticated opening inventory and durable private broker order receipts. Real placement, cancellation and owner activation were not performed.

## Implementation and independent review

- Initial actual THB/BTC is imported once as an immutable opening wallet. Capital and day-start performance use full bid-marked equity, not cash alone. Existing manually bought BTC is an asset; no fabricated application BUY, fill, cost basis or profit is created. Two signed matching wallet observations, current Trade permission, no open orders/reservations and exact key/account binding remain required. Unsupported assets fail closed.
- Reconciliation uses the immutable opening timestamp for the trading epoch, retaining detection of foreign fills between provisioning and activation. Later deposits, coin changes or a second provisioning cannot reset the ledger, opening balance, Stop or losses. PostgreSQL rejects changed/removed opening data; missing/null opening properties remain compatible for legacy cash-only accounts.
- The server-owned private WebSocket subscribes to order_update before sending can be enabled. It uses a bounded trusted TLS connection, authenticated server timestamp, heartbeat and reconnection. API credentials stay only in the owner executor. Parsed receipts omit broker user IDs and all auth material. The observer writes a separate append-only journal so it does not contend with the executor's account lock or mutate portfolios.
- The new receipt accounting mode makes no global REST cash-fee assumption. Each owned order's REST history and order detail must match an authenticated cumulative receipt with explicit executed amount, received units, total fee, credits and wallet fee. Exact candidate financial effects must agree; indistinguishable fully credited candidates produce identical fills. Wallet equality alone never selects a fee mode. A missing receipt does not fall back to guessing from REST or mark a request rejected.
- Receipt identities are scoped to account, credential fingerprint, order and update timestamp. Replayed identical evidence is idempotent. Conflicting evidence remains in a separate immutable conflict journal and blocks reads/new receipt processing across restart. A timestamp collision with different payload fails closed and requires investigation; it is not silently resolved.
- Owner preflight, coordinator readiness, preparation and dispatch require the receipt observer to be ready for this mode. Loss of transport can reconnect; unknown financial outcomes are never replayed. Missing events while disconnected require independent recovery, because the private stream does not provide historical replay.
- Coordinator sizing now uses approved order limits and remaining daily turnover, including fee headroom and pending orders. SELL/TRIM respect owned unreserved coins and base quantum. This fixes the zero-cash initial-BTC case where selling all holdings would exceed a full-equity limit once fee headroom was included. RiskEngine remains final authority.
- Earlier fixes remain: exact broker open-buy reserves within conservative local reserves, current Trade permission on all owner preflights, graceful meeting interruption saved without resubmission, and legacy canary support within the REST archive boundary. Abrupt STARTED claims remain blocked; no financial uncertainty is cleared automatically.

The lead inspected actual production changes and worker test diffs, reviewed financial/account binding and compatibility directly, and used existing framework/library seams. No dependencies, withdrawal, transfer, margin, leverage or shorting were added. Broker secrets and real account captures were not sent to supporting agents. After a supporting worker hit its usage limit, the lead completed the durable-conflict changes and tests directly.

Docker build progress on stderr combined with ErrorActionPreference=Stop reproduced a terminating NativeCommandError even when the command succeeded, before configuration changes or activation.

The lead reviewed and corrected the bounded worker patch: a local Docker helper captures stdout/stderr under scoped Continue, reads the global native exit variable, restores Stop before logging/file handling, renders native text without PowerShell error formatting and returns only the integer exit code. All activation and rollback stages still check their original nonzero failure gates. Missing native exit codes and log write errors fail closed. The wrapper still uses the owner's manual activation action; no financial authority was opened during repair.
