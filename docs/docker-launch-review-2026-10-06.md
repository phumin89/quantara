# Docker launch repair: 2026-10-06

Reproduced: Docker's HTTP/IP link to port 3000 fails before routing, while normal certificate-validated `https://localhost:3000` returns 200. The application and owner identity require the canonical HTTPS hostname. A TLS listener cannot issue an HTTP redirect before a failed TLS handshake; certificate validation was not relaxed.

Added a conventional loopback-only HTTP entry on host/container port 2080 in the existing owner service. Both port numbers sort before the existing app/API ports so `2080:2080` is easy to find. It accepts only GET/HEAD for `/`, `/account`, `/trading` from known loopback hosts and issues a fixed 302 to the canonical HTTPS page. Query strings are discarded. No proxying, authentication, cookies, owner data or financial actions occur on HTTP. Existing HTTPS ports, identity, origin/CSRF controls and remembered viewing remain intact. The launcher checks port 2080 availability; no additional service or dependency was added.
