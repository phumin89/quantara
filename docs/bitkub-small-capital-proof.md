# เปิด Auto Spot ด้วยบัญชีจริง

ไม่ต้องขายเหรียญเดิมหรือทำรอบซื้อ–ขายมือเพื่อเปิดระบบ แอปรับ THB และ BTC/ETH/SOL ที่ profile รองรับเป็นทรัพย์สินเริ่มต้นครั้งเดียว และใช้ผลคำสั่งจากช่องทางส่วนตัวของ Bitkub ตรวจยอดที่หัก จำนวนเหรียญที่ได้รับและค่าธรรมเนียมก่อนลงบัญชี รายการมือก่อนเริ่มบัญชีไม่ถูกสร้างใหม่เป็นรายการของแอป

## เตรียม profile แบบอ่านข้อมูล

สำหรับการเตรียม profile ใหม่ เก็บข้อมูลปัจจุบันด้วย `tools/bitkub-proof.ps1` แล้วใช้ `tools/bitkub-proof.ps1 -Captures <ไฟล์ล่าสุด> -OrderReceipts` ภายใน 5 นาที เครื่องมือตรวจสิทธิ์ Trade, ยอดสองครั้ง, คำสั่งค้าง, ประวัติ, กติกา BTC/ETH/SOL และการยืนยัน/สมัคร private order stream ก่อนเขียน profile ใน `.runtime/live/bitkub-verification.json` ต้องไม่มีคำสั่งค้างและสินทรัพย์ที่ยังไม่รองรับ เส้นทางเก็บหลักฐานประวัติ/รายละเอียดเดิมยังรองรับประวัติ BTC เท่านั้น หากมีประวัติ ETH/SOL ต้องขยายตัวเก็บหลักฐานก่อนใช้เส้นทางนี้ บัญชี BTC ที่มี profile แบบ private receipts อยู่แล้วใช้ตัวเปิดด้านล่างได้โดยไม่ต้องเก็บหลักฐานใหม่ การเตรียมนี้ไม่เปิดการส่งคำสั่ง ไม่เริ่ม CEO และไม่ต้องจับคู่เบราว์เซอร์ใหม่

กุญแจอยู่ใน `.env` ของโครงการเท่านั้น ห้ามส่งกุญแจหรือไฟล์หลักฐานในแชต ส่วน API key, secret, signature และ token ไม่เข้าแชตทีม เบราว์เซอร์ โมเดลหรือ log

## เจ้าของเปิดใช้งาน

เปิด `Enable Auto Trading.cmd` เมื่อพร้อมให้ระบบส่งคำสั่งเงินจริง ตัวเปิดใช้ PowerShell แบบไม่มี profile และข้ามข้อจำกัด script เฉพาะ process นี้ ไม่เปลี่ยนนโยบาย Windows ถาวร

ตัวเปิดตรวจตลาด BTC, ETH และ SOL จาก Bitkub แล้วขยาย profile แบบมีสำรองไฟล์เดิม ก่อนเปิดสิทธิ์เจ้าของสำหรับเหรียญที่ตรวจผ่าน บัญชีเดิมเก็บวงเงิน จำนวนสถานะสูงสุด ประวัติ ขาดทุนและปุ่มหยุดไว้ครบ การเพิ่มเหรียญไม่เพิ่มเพดานความเสี่ยง ตัวรับผลคำสั่งและการตรวจยอดต้องผ่านก่อนเริ่มทีมที่แยกจากกุญแจโบรกเกอร์

ทีมประชุมใหญ่ครบ 8 บทบาทตั้งแต่ 09:00 กรุงเทพ และเปรียบเทียบ BTC/ETH/SOL ระหว่างวันจะทบทวนพอร์ตด้วยผู้จัดการพอร์ตและทีมความเสี่ยง 3 บทบาทเมื่อยอดหรือจำนวนเหรียญเปลี่ยน หรือราคา bid/ask เปลี่ยนอย่างน้อย 1% จากรอบก่อน โดยจำกัดชั่วโมงละรอบและไม่เรียก AI ซ้ำเมื่อข้อมูลไม่เปลี่ยน รายงานเลือกอ่านแยกตามรอบได้ เฝ้าตลาดได้ตลอดวันรวมก่อน 09:00 หลังมีข้อมูลรอบแรกแล้ว

ทีมอาจเลือก HOLD หรือเสนอซื้อ ลดสัดส่วน หรือขายจากยอดที่เป็นเจ้าของ เหรียญที่ยังไม่มีสิทธิ์เป็นข้อมูลวิจัยเท่านั้น RiskEngine ตรวจคำสั่งสุดท้ายและรอผลจาก Bitkub ก่อนรับรู้ยอด ระหว่างคำสั่งค้างจะไม่เริ่มรอบใหม่ ไม่ส่งคำสั่งเดิมซ้ำเมื่อเปิดแอปใหม่หรือผลไม่แน่นอน

นโยบายที่เจ้าของเลือกไว้: ทุนเริ่มต้นคือมูลค่า THB+BTC จริงที่ราคา bid; เพดานงบรวม ต่อคำสั่ง turnover ต่อวันและขาดทุนต่อวันเท่าทุนเริ่มต้น; drawdown/exposure สูงสุด 100%, slippage สูงสุด 2% และสำรองค่าธรรมเนียมตาม profile ระบบลดขนาดคำสั่งให้ผ่านเพดานและขั้นต่ำ ไม่ขายเหรียญเกินยอดที่ว่าง บัญชีเดิมไม่เพิ่มวงเงิน ไม่ล้าง Stop หรือรีเซ็ตขาดทุน

`Quantara.cmd` ใช้เปิดดูแอปตามปกติ การจับคู่มีไว้ยืนยันสิทธิ์เบราว์เซอร์ ไม่ใช่การเปิด Auto หลัง executor รีสตาร์ตต้องตรวจและเปิดสิทธิ์การเทรดใหม่ ประวัติและยอดยังอยู่ใน volume เดิม

## การตรวจผลและการหยุด

ผล `order_update` ที่ยืนยันตัวตนแล้วเก็บเป็นหลักฐานเพิ่มอย่างเดียวใน PostgreSQL และเทียบกับประวัติ REST รายละเอียดคำสั่งที่แอปเป็นเจ้าของ และยอดกระเป๋าสองครั้ง ยอดผลคำสั่งรองรับทั้งค่าธรรมเนียมที่จ่ายจากกระเป๋าและเครดิต ไม่เดาวิธีหักค่าธรรมเนียมจากความเปลี่ยนแปลงของกระเป๋าเพียงอย่างเดียว

ข้อมูลขาดหรือขัดแย้งหยุดการส่งใหม่และคงยอดเดิม ข้อมูลที่ขัดแย้งถูกเก็บเป็นเหตุหยุดถาวรข้าม restart; ห้ามลบ marker, ledger, journal หรือ volume เพื่อให้ผ่าน เมื่อ stream หายระหว่างคำสั่งและไม่มี receipt ย้อนหลัง ต้องตรวจผลนั้นก่อนเปิดใหม่ ระบบไม่ถือว่ารายการหายคือรายการล้มเหลว

การย้อนรุ่น: หยุด company และปิด Live execution ก่อนเปลี่ยน image; คง schema, profile และ volume ไว้ ไม่ downgrade executor ที่กำลัง Armed หรือเขียนทับ opening inventory รุ่นเก่าอ่าน profile แบบ receipt ไม่ได้และต้องหยุด ข้อมูลบัญชีแบบ cash-only เดิมยังอ่านได้ในรุ่นใหม่

เส้นทาง canary สามไฟล์เดิมยังมีสำหรับหลักฐาน REST ที่ยืนยันครบแล้ว แต่ไม่ใช่เงื่อนไขเริ่มระบบแบบ receipt ผลทดสอบจำลองและการเชื่อมต่อสำเร็จยังไม่ใช่หลักฐานว่าแอปได้เทรดจริง ต้องตรวจคำสั่งที่แอปส่ง ผลรับจริงและการกู้สถานะโดยไม่ส่งซ้ำหลังเจ้าของเปิดระบบ
