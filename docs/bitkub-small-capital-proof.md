# ยืนยันการซื้อขายด้วยทุนเล็ก

ข้อเสนอนี้ยังไม่ใช่การอนุญาตส่งคำสั่งหรือเปิด CEO อัตโนมัติ ตรวจเมื่อ 6 ตุลาคม 2026: อ่านบัญชีและตรวจสิทธิ์ Trade ผ่าน ยอด THB 0 ไม่มีเหรียญ คำสั่งค้าง หรือประวัติซื้อขายในสามคู่ที่รองรับ

เป้าหมายคือยืนยันเงินและเหรียญที่ Bitkub หัก/เพิ่มจริง ก่อนเลือกวิธีปัดจำนวนในระบบ หลักฐานทดสอบ HTTP จำลองใช้แทนขั้นนี้ไม่ได้ เลือกได้สองทาง: ใช้คำยืนยันพร้อมตัวอย่างจาก Bitkub หรือให้เจ้าของกดยืนยันรายการเล็กบน Bitkub แล้วเก็บข้อมูลก่อน–หลังด้วยตัวอ่านของโครงการ

## ทางเลือก: เจ้าของยืนยันรายการบน Bitkub

1. เจ้าของเลือกทุนทดลองเอง หลังมี THB ในบัญชีให้เก็บข้อมูลตั้งต้นใหม่ ต้องไม่มีเหรียญและคำสั่งค้าง ใช้กุญแจเดิม ไม่ต้องส่งกุญแจในแชต
2. เก็บภาพข้อมูลจาก API ด้วย `BitkubAccountCheck --capture-evidence-env` ตัวอ่านนี้ไม่ส่งคำสั่ง ไม่ถอนเงิน และไม่เปิดการเทรด ผมสามารถรันและตรวจผลให้ได้ ไม่ต้องเปิดหน้าต่างจับคู่ใหม่เพื่อใช้ตัวอ่าน
3. เจ้าของยืนยันคำสั่ง **limit ซื้อ BTC** บน Bitkub โดยดูยอดหักรวมค่าธรรมเนียมก่อนยืนยัน ตัวอย่างเพดานสำหรับการพิสูจน์ครั้งเดียวคือ 30 บาท; ยังไม่ได้รับอนุมัติเพดานนี้ และยังไม่ใช่วงเงิน CEO หากยอดต่ำกว่าขั้นต่ำของ Bitkub ต้องหยุดตรวจแทนการเพิ่มยอดเอง
4. เมื่อคำสั่งมีผลแน่นอน เก็บข้อมูลอีกครั้ง ตรวจรหัสรายการ ยอด THB ที่หัก เหรียญที่ได้รับ ค่าธรรมเนียมและเครดิตจากทั้งกระเป๋า ประวัติ และรายละเอียดคำสั่ง ถ้าคำสั่งยังค้างหรือข้อมูลเปลี่ยนระหว่างอ่าน ให้รอผลแน่นอนก่อนสรุป
5. เจ้าของยืนยันคำสั่ง **limit ขายเหรียญที่ได้จากข้อ 3** แล้วเก็บข้อมูลหลังขาย ตรวจยอดเงินรับสุทธิและเหรียญที่เหลือ การขายเป็นการยืนยันอีกคำสั่งหนึ่ง ไม่เกิดอัตโนมัติจากการอนุมัติซื้อ
6. Lead ตรวจสมการก่อนเลือก verified profile: quote ก่อน/รวม cash fee, fee ลบเครดิต, จำนวนเหรียญตรงกับการปัดที่ยืนยัน, ยอดเงินหลังขาย และความสัมพันธ์รหัสคำสั่ง ต้องได้คำตอบเดียวที่ตรงกับข้อมูลจริง ถ้าผลยังคลุมเครือ ต้องใช้คำยืนยันจาก Bitkub; ห้ามเลือกวิธีที่ดูเหมือนใกล้เคียง

ระหว่างสามภาพข้อมูลต้องไม่มีฝากเงินหรือรายการอื่นที่ทำให้แยกผลไม่ได้ การพิสูจน์นี้อาจเสียค่าธรรมเนียมหรือขาดทุนจากราคา ไม่ใช่การทดลองผลกำไรของกลยุทธ์

ตัวอ่านเก็บไฟล์ชื่อเฉพาะในโฟลเดอร์ `.runtime` ที่ไม่ขึ้น GitHub มีรหัสรายการและยอดเงินเพื่อเทียบหลักฐาน ไม่มี API key, secret, signature หรือ token จำกัดไม่เกิน 20 ประวัติต่อคู่เพื่อเก็บชุดทดสอบครบโดยไม่ตัดข้อมูลเงียบ ๆ หากเก็บไม่ครบจะระบุว่าไม่สำเร็จ

## หลังหลักฐานผ่าน

ผูกบัญชีกับกุญแจและหลักฐานที่ตรวจแล้ว เตรียมบัญชีจริงพร้อมวงเงินเจ้าของ ตรวจยอดตั้งต้นและเปิดใช้งานผ่านหน้าแอปแยกกัน จากนั้นจึงเสนอคำสั่งทดสอบจากแอปพร้อมยอดและราคาให้เจ้าของอนุมัติ การทดสอบบน Bitkub ข้างต้นไม่ได้เปิดสิทธิ์ให้ CEO ซื้อขาย

เงื่อนไขรับงาน: คำสั่งจริงจากแอปหนึ่งรายการมีผลจาก Bitkub ตรวจเงิน/เหรียญตรงกัน เก็บลงฐานข้อมูล เปิดระบบใหม่แล้วกู้ผลเดิมโดยไม่ส่งซ้ำ คำสั่งที่ไม่ทราบผลต้องหยุดการส่ง ไม่อนุมานว่าไม่สำเร็จแล้วลองใหม่

กฎโครงการ [AGENTS.md](../AGENTS.md) ระบุ: “Live implementation is authorized; activation and real-money transactions are not.” จึงต้องให้เจ้าของยืนยันก่อนเริ่มรายการเงินจริงตามขั้นที่เลือก

แหล่งสัญญา API: [REST V3](https://github.com/bitkub/bitkub-official-api-docs/blob/master/rest-v3.md), [Private order updates](https://github.com/bitkub/bitkub-official-api-docs/blob/master/websocket-private.md) เอกสารระบุหน่วย quote/base และค่าธรรมเนียม แต่ไม่ได้พิสูจน์วิธีปัดต่อ fill กับยอดกระเป๋าของบัญชีนี้
