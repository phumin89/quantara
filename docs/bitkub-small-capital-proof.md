# ยืนยันการซื้อขายด้วยทุนเล็ก

เจ้าของขอเปิด Live แล้วเมื่อ 6 ตุลาคม 2026 และเลือกใช้งบจากพอร์ตทั้งหมดในขอบเขต Spot ไม่ต้องถามวงเงินทั้งสี่ซ้ำ การเปิดยังต้องผ่านหลักฐานโบรกเกอร์และตรวจยอดจริง อ่านบัญชีและตรวจสิทธิ์ Trade ผ่านแล้ว และเก็บหลักฐานหลังคำสั่ง Market ซื้อที่เจ้าของทำเองได้ครบ ตัวอ่านของโครงการยังไม่ส่งคำสั่งเงินจริง

เป้าหมายคือยืนยันเงินและเหรียญที่ Bitkub หัก/เพิ่มจริง ก่อนเลือกวิธีปัดจำนวนในระบบ หลักฐานทดสอบ HTTP จำลองใช้แทนขั้นนี้ไม่ได้ เลือกได้สองทาง: ใช้คำยืนยันพร้อมตัวอย่างจาก Bitkub หรือให้เจ้าของกดยืนยันรายการเล็กบน Bitkub แล้วเก็บข้อมูลก่อน–หลังด้วยตัวอ่านของโครงการ

## ทางเลือก: เจ้าของยืนยันรายการบน Bitkub

1. เจ้าของเลือกทุนทดลองเอง หลังมี THB ในบัญชีให้เก็บข้อมูลตั้งต้นใหม่ ต้องไม่มีเหรียญและคำสั่งค้าง ใช้กุญแจเดิม ไม่ต้องส่งกุญแจในแชต
2. เก็บภาพข้อมูลจาก API ด้วย `pwsh -NoProfile -File tools/bitkub-proof.ps1` ตัวอ่านนี้ทำงานผ่าน Docker ไม่ส่งคำสั่ง ไม่ถอนเงิน และไม่เปิดการเทรด แสดงชื่อไฟล์หลักฐานที่เก็บไว้ ไม่ต้องเปิดหน้าต่างจับคู่ใหม่เพื่อใช้ตัวอ่าน
3. เจ้าของยืนยันคำสั่ง **Limit หรือ Market ซื้อ BTC** บน Bitkub โดยดูยอดหักรวมค่าธรรมเนียมก่อนยืนยัน เลือกยอดเล็กเป็นจำนวนเต็ม THB ที่ผ่านขั้นต่ำของ Bitkub แล้วเก็บข้อมูลอีกครั้งด้วยคำสั่งเดียวกับข้อ 2 ขั้นแรกนี้รองรับ BTC เท่านั้น ไม่ยกผล BTC ไปยืนยันคู่เหรียญอื่น
4. เมื่อคำสั่งมีผลแน่นอน เก็บข้อมูลอีกครั้ง ตรวจรหัสรายการ ยอด THB ที่หัก เหรียญที่ได้รับ ค่าธรรมเนียมและเครดิตจากทั้งกระเป๋า ประวัติ และรายละเอียดคำสั่ง ถ้าคำสั่งยังค้างหรือข้อมูลเปลี่ยนระหว่างอ่าน ให้รอผลแน่นอนก่อนสรุป
5. เจ้าของยืนยันคำสั่ง **Limit หรือ Market ขายเฉพาะเหรียญที่ได้จากข้อ 3** แล้วเก็บข้อมูลหลังขาย ตรวจยอดเงินรับสุทธิและเหรียญที่เหลือ การขายเป็นการยืนยันอีกคำสั่งหนึ่ง ไม่เกิดอัตโนมัติจากการอนุมัติซื้อ
6. ใช้ `tools/bitkub-proof.ps1 -Captures <ไฟล์ก่อน>,<ไฟล์หลังซื้อ>,<ไฟล์หลังขาย>` ตรวจสมการก่อนเลือก verified profile: quote ก่อน/รวม cash fee, fee ลบเครดิต, จำนวนเหรียญตรงกับการปัดที่ยืนยัน, ยอดเงินหลังขาย และความสัมพันธ์รหัสคำสั่ง ต้องได้คำตอบเดียวที่ตรงกับข้อมูลจริง ถ้าผลยังคลุมเครือ ต้องใช้คำยืนยันจาก Bitkub; ห้ามเลือกวิธีที่ดูเหมือนใกล้เคียง เครื่องมืออ่านกุญแจ สิทธิ์ Trade กระเป๋าและคำสั่งค้างใหม่ก่อนเขียน profile และยังไม่เปิดสิทธิ์เทรด

ระหว่างสามภาพข้อมูลต้องไม่มีฝากเงินหรือรายการอื่นที่ทำให้แยกผลไม่ได้ การพิสูจน์นี้อาจเสียค่าธรรมเนียมหรือขาดทุนจากราคา ไม่ใช่การทดลองผลกำไรของกลยุทธ์

ภาพข้อมูลประวัติต้องมีอายุน้อยกว่า 90 วันเพื่อยังตรวจรายการจาก Bitkub ก่อนเข้า archive ได้ ข้อมูลตลาดต้องใหม่ภายใน 60 วินาทีของการเก็บแต่ละครั้ง และเวลาซื้อ–ขายต้องเกิดหลังภาพข้อมูลขั้นก่อนหน้า ตัวตรวจอ่านกุญแจ สิทธิ์ กระเป๋า ประวัติ รายละเอียดคำสั่งและกติกาตลาดปัจจุบันมาเทียบอีกครั้งก่อนเขียน profile หลักฐานเก่าไม่อนุญาตใช้ยอดเงินเก่าเปิดเทรด การเว้นช่วงข้ามวันจึงไม่บังคับให้เจ้าของทำรายการเล็กซ้ำเพราะไฟล์เกินกำหนด 24 ชั่วโมงเดิม

Market อาจส่งราคาในหัวคำสั่งเป็นศูนย์ ตัวตรวจใช้ราคาที่จับคู่จริงซึ่งต้องเป็นบวกและตรงกับประวัติทั้งหมด รองรับจำนวนในรายละเอียดคำสั่งทั้งตัวเลขและข้อความโดยไม่ปัดทศนิยมเงียบ ๆ การอ่านหลักฐาน Market ไม่เพิ่มสิทธิ์ให้แอปส่ง Market; ตัวส่งและการตรวจยอด Live ยังคงรองรับเฉพาะ Limit ที่แอปเป็นเจ้าของ

ถ้าค่าธรรมเนียมซื้อถูกเครดิตชดเชยทั้งหมด ตัวตรวจแจ้ง `BITKUB_BUY_CASH_FEE_NOT_PROVEN` เพราะยังแยกไม่ได้ว่า `amount` รวมค่าธรรมเนียมที่หักเป็น THB หรือไม่ ห้ามเลือกวิธีบัญชีจากการเดาหรือใช้ยอดกระเป๋าอย่างเดียวแทนหลักฐาน ต้องใช้รายการที่มี cash fee จริงหรือคำยืนยันจาก Bitkub **ไม่ควรทำรายการซ้ำเพื่อใช้เครดิตให้หมด** คำถามที่ต้องยืนยัน: สำหรับ fill ซื้อใน REST V3 ค่า `amount` รวม `fee - credit` หรือไม่ และจำนวน BTC ที่ได้รับคำนวณ/ปัดต่อ fill อย่างไร

ตัวอ่านเก็บไฟล์ชื่อเฉพาะในโฟลเดอร์ `.runtime` ที่ไม่ขึ้น GitHub มีรหัสรายการและยอดเงินเพื่อเทียบหลักฐาน ไม่มี API key, secret, signature หรือ token จำกัดไม่เกิน 20 ประวัติต่อคู่เพื่อเก็บชุดทดสอบครบโดยไม่ตัดข้อมูลเงียบ ๆ หากเก็บไม่ครบจะระบุว่าไม่สำเร็จ

## หลังหลักฐานผ่าน

เจ้าของรัน `pwsh -NoProfile -File tools/activate-live.ps1` เพื่อเปิดใช้งานตามนโยบาย Spot ที่เลือกไว้ เครื่องมือตรวจ profile/กุญแจ/สิทธิ์ปัจจุบันก่อนแก้ configuration หยุด CEO ระหว่างเปิดระบบ เตรียมบัญชีจาก THB ที่อ่านจริง ตรวจยอดตั้งต้น และเปิด owner gate ผ่านบริการเดิม จากนั้นจึงเริ่ม CEO ที่แยกจากกุญแจโบรกเกอร์ คำสั่งเปิดนี้ไม่ส่งคำสั่งซื้อขายเอง แต่การเริ่ม CEO หลังเปิด gate อนุญาตให้ข้อเสนอ Spot ที่ผ่าน RiskEngine ส่งเงินจริงได้ จึงเป็นคำสั่งสำหรับเจ้าของใช้เปิดระบบโดยตั้งใจ

บัญชีใหม่: งบรวม/ต่อคำสั่ง/turnover ต่อวัน/ขาดทุนต่อวันเท่าทุนจริง พอร์ตลดลงและ exposure สูงสุด 100%, slippage สูงสุด 2%, สำรองค่าธรรมเนียมตาม profile, rollover วันกรุงเทพอัตโนมัติ บัญชีเดิมไม่เพิ่มวงเงิน ไม่ล้าง Stop และไม่รีเซ็ตขาดทุน การรีสตาร์ต executor ยังคงหยุดอำนาจเดิมก่อนตรวจและให้เจ้าของเปิดใหม่ การจับคู่เบราว์เซอร์ใช้เพื่อเข้าดู ไม่ใช่การเปิดเทรด

เงื่อนไขรับงาน: คำสั่งจริงจากแอปหนึ่งรายการมีผลจาก Bitkub ตรวจเงิน/เหรียญตรงกัน เก็บลงฐานข้อมูล เปิดระบบใหม่แล้วกู้ผลเดิมโดยไม่ส่งซ้ำ คำสั่งที่ไม่ทราบผลต้องหยุดการส่ง ไม่อนุมานว่าไม่สำเร็จแล้วลองใหม่

คำขอเปิด Live ล่าสุดของเจ้าของมาก่อนข้อความอนุญาตรุ่นเก่าใน [AGENTS.md](../AGENTS.md) แต่ไม่ทำให้ข้ามหลักฐานโบรกเกอร์ วงเงินจริง การตรวจยอด หรือ Stop ได้ ไม่มีการเปิดระบบหรือกดยืนยันรายการแทนเจ้าของในรอบนี้

แหล่งสัญญา API: [REST V3](https://github.com/bitkub/bitkub-official-api-docs/blob/master/rest-v3.md), [Private order updates](https://github.com/bitkub/bitkub-official-api-docs/blob/master/websocket-private.md) เอกสารระบุหน่วย quote/base และค่าธรรมเนียม แต่ไม่ได้พิสูจน์วิธีปัดต่อ fill กับยอดกระเป๋าของบัญชีนี้
